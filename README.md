# Gembase — client

Web client for **Gembase**, a platform that helped game studios evaluate game concepts *before* building an MVP:
describe a concept with a title, description and tags, and Gembase finds the closest competitors on Google Play and
scores the concept's threats and opportunities, based on ~40,000 LLM-tagged apps and surveys of thousands of players.

The backend lives in [gembase.io-server](../gembase.io-server).

> Gembase was a two-person startup (2022–2024). My partner owned the product vision, design and evaluation
> methodology; I built the whole technical side — this client, the Python server, the scraping pipeline and the
> LLM integration. The product was shut down; the code is published as a portfolio piece and is not actively
> maintained.

## Tech stack

Vue 3 (Composition API) · TypeScript · Vite · Pinia · Vue Router · Tailwind CSS · amCharts 5

## What's inside

The app has three parts:

- **Landing pages** — marketing site, sign-in / sign-up, legal pages (`views/home`, `views/legals`)
- **Platform** (`views/platform/modules`) — the product itself:
  - **Auditor** — create a game concept, tag it and get competitors and a threat score
  - **Games Explorer** — browse and compare the scraped market (comparison map, KPI charts, segments)
  - **Player Explorer** — explore the survey data by audience segments
  - **Gaps** — search for market gaps and opportunities
  - **Studies** — create and preview player surveys for your own concepts
  - **Account / Billing / Admin** — licences, Stripe checkout, user management, whitelist, email composer
- **Survey** (`views/survey/v2`) — the public survey that players filled in

## Notable implementation details

- **State kept in the URL** — the platform's pages are heavily interlinked, so view state lives in
  query parameters. `useQueryModel` (`src/router/queryModelComposable.ts`) keeps a reactive `ref`
  and the route query in two-way sync. Every view is shareable, bookmarkable and survives a reload,
  and navigating between pages just means passing a query.
- **Command API client** — `src/commands/base/baseCommands.ts` wraps the server's command endpoints
  (`POST /commands/<group>` with `{ id, payload }`) in typed methods per area (`portalCommands`,
  `calcCommands`, `billingCommands`...), with JWT auth, file upload/download and response hooks
  (for example, updating the user's credits after each call).
- **Long-running calculations** — evaluations run in server-side worker processes; the client
  queues them and polls progress (`models/portal/calc`, `PlatformValuesServiceChecker`), so the UI
  stays responsive.
- **Obfuscated IDs** — all app / developer / tag ids the client sees are per-client obfuscated
  values generated by the server.
- **Custom design system** — Tailwind theme and plugins in `src/tailwind`, plus a set of reusable
  `Gb*` UI components (buttons, popups, sliders, range sliders, tooltips) in `views/ui`.

## Project structure

```
src/
  commands/      Typed wrappers around the server command API
  models/        Pinia stores and data models per platform module
  router/        Routes (home, portal, survey) and the URL-query composable
  views/         Pages and components (home, platform, survey, ui)
  tailwind/      Theme, palette and Tailwind plugins
  errors/        Client / server error types and the global error handler
  appEnv.ts      Environment config (reads VITE_APP_* variables)
```

## Running with Docker

The client has a multi-stage `Dockerfile`: Node builds the app, and the final image is just nginx serving
`dist/` (`nginx.conf` includes the history-mode fallback). The easiest way to run it is together with the API
and database, using the `docker-compose.yml` in [gembase.io-server](../gembase.io-server):

```bash
# in gembase.io-server, with gembase.io-client cloned next to it
cp docker.env.example docker.env
docker compose up --build
```

The client is then available at http://localhost:8080. The API address is baked in at build time through the
`VITE_APP_SERVER_ROOT` build argument.

## Running locally

Requires Node.js 22+.

```bash
npm install
```

Create a `.env` file (git-ignored):

```ini
VITE_APP_ENV=dev                               # dev | test | prod
VITE_APP_SERVER_ROOT=http://localhost:5000     # URL of gembase.io-server
```

```bash
npm run dev        # dev server
npm run build      # type-check + production build into dist/
npm run lint       # ESLint
npm run format     # Prettier
```

For production builds, put the values in `.env.production`. `dist/` is a static site; serve it with
any web server (nginx with an `index.html` fallback for client-side routes).
